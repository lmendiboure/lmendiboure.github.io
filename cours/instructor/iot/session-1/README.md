# Session 1 instructor surfaces

- `index.html` — **Projector Mode**, safe to screen-share and sufficient for live facilitation.
- `notes.html` — **preparation sheet**, not a live dashboard. Read it before class; do not try to operate it while teaching.

## Canonical flow

Session 1 now has six canonical activities:

1. Test the IoT boundary
2. Build a defensible baseline
3. From monitoring to control
4. Expose per-flow communication requirements
5. From network shape to technology family — one two-step activity
6. Defend the campus communication strategy

The former stress-test/revision activity is intentionally relocated to Session 4 (Robustness).

## Split-class resumption

The next class should resume with the dedicated **Projector recap**, then continue directly at **Activity 5**. The recap gives the prior learning explicitly; it does not quiz students on what they remember.

- Student: `../../../iot/session-1/?activity=5` or click Activity 5 in the always-open activity bar.
- Projector recap: open `?recap=1` or press `R`; its Next button goes directly to Activity 5.
- Projector direct jump: `?activity=5` or press the number key `5`.

No earlier activity must be marked complete to resume.

## Live projector controls

- Right arrow / Space: next public screen.
- Left arrow: previous public screen.
- Number keys `1`–`9`: jump directly to that activity WORK screen.
- `R`: open the restart recap (Session 1 only, when recap data exists).
- `F`: fullscreen.

The live sequence remains deliberately minimal: **ACTIVITY → optional CLASS DISCUSSION → one flip card → NEXT → static conclusion**.

## Mission dossier

Session 1 hands Session 2 only compact structured context: communication-path class, dominant communication requirements, campus access stance, key uncertainty and baseline assumption. Robustness/revision state belongs to Session 4, not the S1→S2 handover.
