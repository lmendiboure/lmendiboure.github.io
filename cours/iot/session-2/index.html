ONE QUESTION FIRST

What interaction does the service need?

Use the arrows and the service description. Choose the interaction that best captures what the service requires in each case. These are reference patterns: a real system can combine several of them.

ONE-WAYproducer → receiversend an update; no reply is part of the service exchange
REQUEST / RESPONSErequest → responseone side asks for a resource or current state
PUBLISH / SUBSCRIBEpublisher → intermediary → subscribersone update can reach several interested consumers
COMMAND / ACKcommand → digital acknowledgementa command is accepted/rejected; physical feedback remains a separate question from S1

Class discussion

Interaction first. Protocol later.

ONE-WAYproducer → receiverNo reply is part of the service interaction.
REQUEST / RESPONSErequest → responseA requester asks for state/resource/action and expects a reply.
PUBLISH / SUBSCRIBEpublisher → broker → subscribersProducers and consumers are decoupled; one publication can feed several consumers.
COMMAND / ACKcommand → ACKThe ACK concerns digital handling; physical-state evidence remains separate.
Reference patterns, not rigid boxesA real IoT system can use several interaction patterns at once; the point is to identify the interaction needed by each flow before choosing protocols.
KEEPThe service interaction sits above the protocol stack. It states the exchange we need before choosing how to implement it.

FILL THE MIDDLE ROWS

What carries the application exchange?

Use these simplified reference paths. We are learning where the mechanisms sit; later courses can explore every protocol variant.

TCPOrdered, reliable byte stream between programs.
UDPDatagrams with minimal transport semantics; delivery and ordering are not guaranteed by UDP itself.
IP / IPv6Network addressing and routing so packets can reach another host or network.

Term introduced here — not before

Thread is an IPv6-based low-power mesh networking stack using IEEE 802.15.4 radios. For today, the important point is where this constrained local network solution sits in the complete communication map.

Important nuanceReal technology suites do not always fit perfectly inside one row. The rows represent responsibilities; “Thread over 802.15.4” is our shorthand for the constrained local-network solution in this design map. Other Session 1 families can insert gateway or network-service infrastructure rather than exposing this exact stack end-to-end.
