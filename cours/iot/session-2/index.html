ONE WORD BEFORE THE NAMES

A protocol is an agreed set of communication rules, message formats and behaviours used to perform a particular job. A protocol name therefore tells you which rules are used for a job; it does not describe the whole architecture.

WHY THIS MATTERS

If two names solve different jobs, “A versus B” is usually the wrong comparison. They may belong in the same stack rather than compete.

Activity 8“Reliable” what, exactly?
AM
AminaCampus operations leadAcceptance claim
STARTING POINTThe stack is technically coherent · the acceptance document still says only “the command is reliable”.
NEW INPUT
“A command was acknowledged, the ACK was lost, and the sender retried. The ventilation may now have executed the same logical operation twice.”
DESIGN IMPACTSeparate message delivery from operation execution and from evidence of the physical state.
YOUR MOVE

Say exactly what must be true when the exchange is “successful”.

Different mechanisms can guarantee different objects. Before looking at retry mechanisms or protocol-level delivery settings, distinguish the four scopes below. Then analyse the ACK-loss retry incident.

BytesDid a transport deliver an ordered stream or datagram to an endpoint?
MessageDid the application protocol deliver/acknowledge its message at its own scope?
OperationWas the same logical command processed once, despite retries?
Physical stateDid the real actuator/environment reach the intended state?

Scope means the boundary within which a claim is valid. QoS (Quality of Service) is not a universal “reliability” switch: a QoS level defines behaviour at a particular protocol scope, while the end-to-end service may need additional mechanisms.
